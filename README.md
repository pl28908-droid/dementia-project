# SMARAN — Personalized Cognitive Assistance & Memory Support

SMARAN is a student-built prototype for interactive cognitive activities, behavioral performance analysis, adaptive activity recommendations, and family/caregiver-entered memory support.

## Important scope and safety
- This is **not** a dementia screening, diagnosis, treatment, or clinical decision-support system.
- The ML model predicts a **prototype activity-performance band** (`Good`, `Moderate`, `Needs Attention`) from simulated game-session metrics. These labels are generated by a transparent rule for software-development practice; they are not clinical labels.
- The included dataset is synthetic. Model scores on it do not establish real-world or clinical validity.
- Memory records are supplied by the user/caregiver. The API does not independently verify memories.

## Included
- Reproducible synthetic behavioral dataset generation
- EDA script and ML training/evaluation pipeline
- Scikit-learn preprocessing + Logistic Regression / Random Forest comparison
- Saved end-to-end model pipeline (`.joblib`)
- FastAPI endpoints for users, games, sessions, predictions, recommendations, history and memories
- SQLAlchemy database models (SQLite by default; PostgreSQL via `DATABASE_URL`)
- Simple static landing page (plain HTML/CSS/JS; no React)
- Basic API tests

## Quick start

Python 3.10+ recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python -m src.data.generate_dataset
python -m src.training.train
uvicorn backend.main:app --reload
```

Open:
- Landing page: http://127.0.0.1:8000/
- API documentation: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/health

The first training run creates `models/performance_pipeline.joblib` and evaluation files in `reports/`.

## ML workflow

1. Generate synthetic sessions with a fixed random seed.
2. Inspect distributions and relationships using `src/evaluation/evaluate.py`.
3. Split data into train/test partitions.
4. Fit preprocessing and candidate classifiers inside Scikit-learn pipelines.
5. Compare macro-F1 and class-wise metrics; save the selected complete pipeline.
6. Load the pipeline in the API for inference.

Do not use synthetic performance as evidence that the system works for older adults or people living with dementia. Before any real-world study, obtain appropriate ethical, privacy, and clinical oversight.

## Example API flow

1. `POST /users` — create a profile.
2. `POST /sessions` — record a completed activity session and its metrics.
3. `POST /predict` — predict a prototype performance band.
4. `GET /recommendations/{user_id}` — obtain a rule-based next activity suggestion.
5. `POST /memories` and `GET /memories/{user_id}` — store and retrieve user-provided memory notes.

See `/docs` for request schemas and interactive API exploration.

## Configuration

By default, the app uses SQLite and stores `smaran.db` in the project root.

For PostgreSQL, set an environment variable before starting the app:

```bash
# Example only; replace credentials/database name with your own values.
DATABASE_URL=postgresql+psycopg://username:password@localhost:5432/smaran
```

Never commit real credentials, private memory data, or identifiable personal information. Use `.env` locally and keep it out of Git.
